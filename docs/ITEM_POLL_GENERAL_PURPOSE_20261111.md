# Spoonie 공용 투표 기능 운영 계약 — 2026-11-11

## 실제 범위
투표는 특정 국가·큐레이터·디저트·취향 질문에 고정된 기능이 아니다. 레시피와 레시피드 작성자 누구나 자기 글에 선택적으로 한 개를 추가할 수 있다. 질문 8–160자, 선택지 2–4개(각 2–80자, 중복 금지), 한 사람당 한 표, 선택 변경 가능. 투표 이전에는 결과 수치와 참여자 정보가 보이지 않는다. 참여 후에만 실제 DB 집계 수치와 본인 선택을 표시한다. 레시피·레시피드 작성 UI는 공용 `PollComposer`, 읽기 UI는 공용 `ItemPoll`로 연결한다. 고정 레이블은 중립적인 **투표**.

## 저장·권한·개인정보
- 운영 정본: `public.item_polls`의 `item_id`, `public.item_poll_votes`의 `(item_id, user_id)` 기본 키. 원문 Recipe/Recipeed `description`/`content`와 분리한다.
- 최초 큐레이터 시범 투표와 투표 내역은 그대로 이전한다. 기존 `recipe_polls`는 관리자 이전 호환용 보안 호출자 뷰이며 독립 데이터/중복 큐가 아니다. 기존 `get_recipe_poll`/`cast_recipe_poll_vote` RPC는 과거 배포 코드 호환용 얇은 경로다.
- `get_item_poll`은 공개된 게시물(레시피·레시피드)만 공개 조회하고, 비공개 투표는 게시자만 조회한다. 투표자 ID는 외부 응답에 포함되지 않는다.
- `cast_item_poll_vote`: 실제 로그인한 비편집 계정만 공개 투표에 참여. PK는 계정당 한 표로 고정. 편집 계정은 자가 참여 불가. 선택지 인덱스와 공개 상태를 서버에서 재검증한다.
- `save_item_poll`: DB에서 `auth.uid() = items.user_id`와 게시물 종류, 질문·선택지 형식을 확인한 뒤 저장한다. 이미 참여자가 있으면 질문·선택지 수정 불가. 투표 숨기기는 표를 삭제하지 않고 `active=false`로 비공개화한다.
- 투표자 원본 테이블은 클라이언트에 직접 권한을 주지 않았고 RLS를 활성화했다. SEC DEF RPC는 검색 경로를 고정하고 소유자/로그인/원본 게시물 공개 상태를 함수 본문에서 검증한다.

## 작성·수정 UX
- 두 작성 화면 모두 기본은 ‘투표 추가(선택)’이며 등록이 필수가 아니다.
- 추가를 누르면 질문과 선택지 2개를 바로 편집하고 최대 4개까지 늘린다. 잘못된 입력은 기존 폼 검증과 동일하게 저장을 막고 화면에서 이유를 안내한다.
- 수정 화면에서는 기존 투표 상태를 먼저 읽고, 읽기 실패 시 저장하지 못하도록 한다. 단순히 투표 로딩 실패를 ‘투표 없음’으로 해석하면 기존 투표가 사라지기 때문이다.
- 기존 브라우저 임시 초안에 `poll` 필드가 없는 경우에는 서버의 기존 투표 설정을 복원하고, 최신 초안에 `poll:null`이 명시된 경우에는 작성자가 투표를 제거한 의사를 보존한다.
- 투표 설정은 게시물 저장 성공 직후 별도 보호된 RPC로 저장한다. 현재 Recipe 원본/재료/단계는 `save_recipe_atomic`, Recipeed는 기존 `savePostRow`를 사용한다. **두 호출은 하나의 DB 트랜잭션이 아니다.** 투표 RPC가 실패해도 글 작성 성공을 거짓으로 무효라고 표시하지 않으며, ‘글은 저장됐지만 투표는 반영되지 않음’ 오류를 명확히 알리고 복구 가능한 초안을 남긴다. 장기적으로 단일 SQL 트랜잭션 통합이 필요하면 기존 게시물 저장 함수를 기준으로 확장해야 한다.
- 기존 텍스트 `함께 나눠요 | ...`는 실제 구조화된 투표가 **활성화된 경우에만** 중복 렌더링을 피한다. 일반 사용자 본문/댓글/원작 링크는 절대로 텍스트 치환하거나 삭제하지 않는다.

## 검증
- TypeScript, ESLint, Next.js 프로덕션 빌드, 전체 Vitest 336개 통과.
- 운영 Supabase 마이그레이션 적용 및 이전 시범 투표/익명 원본 투표자 정보 접근차단 확인.
- 실회원 권한 모의 검증은 명시적 DB 트랜잭션으로 실행하고 전체 ROLLBACK하여 테스트 표/투표는 0건 영구 반영한다. 작성자·투표자 변경, 이미 표가 모인 선택지 수정 방어를 검증한다.
- 테스트나 마이그레이션 실행을 실제 회원 활동·투표 참여 성과로 집계하지 않는다.
- 이번 작업은 인스타그램·Threads, 소이/윈도우 Session Supervisor 작업 스케줄과 관계없다.
